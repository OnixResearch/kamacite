## Why

Molten will own the first world-commit schema and canonical Preserves bytes. One Rust implementation and its own fixtures cannot establish an independently reviewable interchange boundary.

Kamacite already owns bounded Nickel, Rust, Steel, and Preserves adapter conformance. It needs a product-schema profile that verifies world-commit values and negative vectors without taking runtime or branch authority.

## What Changes

- Add a versioned Kamacite conformance entry for one immutable Molten world-commit schema and codec cohort.
- Preserve the authoritative Rust schema, fixture source, and canonical packed Preserves bytes as separate identities.
- Add a Nickel source envelope and contract-backed review projection without treating JSON export as canonical identity.
- Add a fresh bounded Steel adapter that consumes only declared DTO or Preserves inputs and has no ambient authority.
- Compare admitted Nickel, Rust, and Steel projections against one canonical Kamacite IR value and exact packed bytes.
- Publish positive vectors for every root and snapshot-profile class.
- Publish negative vectors for malformed, noncanonical, unknown-version, wrong-domain, duplicate, reordered, oversized, stale-schema, embedded-evidence, and authority-overclaim inputs.
- Emit deterministic conformance receipts and optional Valence projections with explicit semantic and runtime non-claims.

## Dependencies

- An implemented and immutable `molten-world-commit-v1` schema and codec revision.
- Kamacite canonical Preserves codec, adapter descriptors, Nickel source envelopes, Steel adapter suite, fixture corpus, and Valence export boundary.

## Non-Goals

- Ownership of Molten world-commit semantics, transition rules, restore, merge, branches, effects, authority, or runtime execution.
- Proof that Nickel, Rust, and Steel evaluators are semantically equivalent.
- A generic stack-wide world protocol or automatic schema migration.
- Acceptance of JSON, source text, Steel bytecode, or opaque closures as canonical world identity.

## Impact

- **Core**: world-commit adapter descriptor, admitted-value checks, domain checks, parity decisions, and deterministic diagnostics.
- **Shell**: pinned fixture intake, reference Nickel export, fresh Steel execution, canonical receipt writing, and explicit update flow.
- **Schemas and fixtures**: conformance entry, source envelopes, canonical values, positive corpus, negative corpus, and golden receipts.
- **Testing**: exact parity plus negative canonicalization, version, domain, bounds, ambient-authority, evidence-role, and semantic-overclaim cases.
